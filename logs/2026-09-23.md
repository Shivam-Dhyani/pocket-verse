## System-bar theming on Android 15+ edge-to-edge

- **What:** A sequence of fixes so the status/navigation bars follow the in-app theme on
  Android 15+ edge-to-edge: give the root element a background, make the bars follow the
  theme, and let the installed app's navigation bar follow the in-app theme (Chrome 153+
  reads the live `theme-color`).
- **Areas:** `apps/web` layout, `lib/theme.ts`, global CSS. Documented in `docs/PWA.md`.

## Theme mode: Match device → then locked to dark

- **What:** Added a Match device / Light / Dark theme preference defaulting to the phone's
  setting — then, per product decision, **locked the app to dark mode** (`FORCED_THEME`),
  hiding the toggle but keeping all light-mode styling in place for later. Added
  per-device iOS launch images and an in-app update prompt (build-id version check;
  iOS standalone apps resume from memory and don't reload on their own).
- **Areas:** `apps/web` theme lib, layout, providers, header, security page, iOS splash
  generator + assets, update-prompt component, `/version.json` route.

## Password-reset email delivery logging

- **What:** Every password-reset request writes one `mail.password_reset` log line with an
  outcome (`sent` / `rejected` / `failed` / `not_configured` / `no_account`), identifying
  the user by `userId` + a masked address (`sh***@g***.com`). The full address and the
  reset link are never logged in production (the link is a live credential; only logged in
  local dev).
- **Areas:** `apps/api` mailer, `lib/mask.ts`, auth service; `docs/DEPLOYMENT.md`.
- **Verification:** added mailer + mask tests asserting the address and link never appear
  in production log output.
