## Phase 3 — core storage engine

- **What:** Resumable uploads (small sequential parts streamed to disk staging, resume
  from last acknowledged part after a restart via `STAGING_LOST` cursor); ≤1.5 GB
  chunking with per-chunk + whole-file sha256 checksums; streaming chunk-by-chunk
  downloads that never buffer bytes in RAM; a retry queue (BullMQ with `REDIS_URL`, an
  in-process runner without); folder CRUD with cycle-proof moves and recursive delete
  that also removes the storage messages.
- **Areas:** files/folders modules, storage worker, queue lib.

  clearer env-validation errors and honest network errors; map database-setup failures
  to honest 503s instead of generic 500s.
- **Why:** Make first-run/local boot fail loudly and legibly.
