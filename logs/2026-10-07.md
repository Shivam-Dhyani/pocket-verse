## Make the ER diagram previewable in any Markdown viewer

- **What:** The one diagram in the repo — the entity-relationship diagram in
  `docs/DATABASE.md` — was a ` ```mermaid ` code block. Mermaid only renders in
  Mermaid-aware viewers (GitHub, some editors); in other previewers it showed as
  raw code. Replaced the code block with a rendered **PNG image** that previews
  everywhere, keeping the Mermaid source for edits.
- **Why:** User reported the diagram showed as code, not a picture, when
  previewing the file.
- **Scope:** Searched every `*.md` in the repo — only `docs/DATABASE.md`
  contained a diagram block (one Mermaid `erDiagram`); nothing else needed
  changing.
- **How:**
  - Rendered the diagram to `docs/images/er-diagram.png` (2× scale, white
    background) with `@mermaid-js/mermaid-cli` driven by the system Chromium.
  - Kept the Mermaid source as the single source of truth at
    `docs/images/er-diagram.mmd`.
  - `docs/DATABASE.md` now embeds the PNG (`![…](images/er-diagram.png)`) with an
    HTML comment giving the regenerate command; no raw diagram code remains in
    the doc.
  - Chose PNG over SVG for maximum compatibility: the Mermaid ER SVG uses a
    `foreignObject` (HTML-in-SVG) that some non-browser renderers don't handle.
- **Areas:** `docs/DATABASE.md`, new `docs/images/er-diagram.png` +
  `docs/images/er-diagram.mmd`; maintenance notes in `docs/DATABASE.md` and
  `.claude/skills/db-architecture-doc/SKILL.md` updated to regenerate the image
  when the schema changes.
- **Verification:** rendered the PNG and confirmed all 8 entities and every
  relationship (crow's-foot notation + labels) are correct and legible; the
  image path is relative and resolves from `docs/`.
