# 2026-09-27

## Move added to the multi-select action bar

- **What:** Selecting any mix of files and folders now shows a **Move** action next to
  Download and Delete. It opens the same folder-picker dialog the single-file row action
  used, generalized to move a whole selection at once.
- **Why:** Multi-select supported download and delete but not move.
- **Areas:** `apps/web` `move-dialog.tsx` (now takes a `MoveSelection` of file ids +
  folder ids + current folder), `drive/page.tsx` (selection-bar Move + `moveSelected`),
  `globals.css` (disabled tree row for a folder that can't be moved into itself).
- **Details:** Files and folders are moved sequentially so one failure (e.g. a folder
  cycle, caught server-side) doesn't abort the batch; selection clears on success.
- **Verification:** typecheck, lint, 144 API tests, web build; headless-browser run of the
  multi-select move (correct `PATCH`es for file `folderId` and folder `parentId`).

## Grid-card select checkbox no longer covers the icon

- **What:** Moved the grid-card selection checkbox from the top-left corner (where it
  overlapped the file/folder icon at larger icon sizes) to the top-right.
- **Why:** At 26px icons the 22px checkbox sat almost entirely on top of the icon once a
  selection made it visible. Google Drive and iCloud both keep the selection badge off the
  icon; this matches that. List view was already fine (checkbox reserves its own space).
- **Areas:** `apps/web/src/app/globals.css` (one rule: `left` → `right`).

## Tap-to-select reliability on touch

- **What:** Added `touch-action: manipulation` to `.pv-row` and `.pv-grid-card`, and
  loosened the long-press move tolerance 10px → 18px.
- **Why:** Selecting off the checkbox relies on our own JS (long-press then tap). Without
  `touch-action`, mobile browsers could treat a held/slightly-drifting finger on padding
  as a scroll or double-tap-zoom check and drop the gesture — so it felt like selection
  only worked right next to the checkbox.
- **Areas:** `globals.css`, `apps/web/src/lib/pointer.ts`.

## Fix: row-actions overflow menu swallowing taps meant for the row

- **What:** A tap in the area around the "⋮" overflow button did nothing — not opening the
  menu, not selecting the card.
- **Root cause:** Mobile Chrome's **touch adjustment** nudges an imprecise tap onto the
  nearest small tappable target, landing the click on the kebab's wrapper `<span>`. That
  wrapper called `stopPropagation()` for _any_ click inside it, so the nudged tap was
  swallowed before it could reach either the button or the row. Confirmed by
  instrumenting a real touch tap (Chrome resolved a tap 8px away onto the wrapper span).
- **Fix:** `stopPropagation()` now lives on each real actionable element (kebab button,
  each menu item, the backdrop, desktop inline buttons), not the wrapper. A tap that
  truly lands on a button still won't select the row; a tap merely nudged into the
  wrapper falls through to the row.
- **Also fixed (found while verifying):** the menu's full-screen dismiss backdrop was
  being trapped inside the grid card's box because `.pv-grid-card:hover` set a `transform`
  and mobile Chrome keeps `:hover` matched on the last-tapped element ("sticky hover") — a
  transformed ancestor becomes the containing block for a `position: fixed` child. The
  hover lift is now gated behind `@media (hover: hover)`.
- **Areas:** `apps/web/src/components/row-actions.tsx`, `globals.css`.
